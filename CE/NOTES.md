# PopSG 技術メモ(SHARP Brain / Windows CE)

コードは AI(Claude)が書きました。製作者はプログラムを読めません。製作者がしたのは、AI への指示と、実機(PW-G5300)での確認です。

PopSG を作る中でわかったことのうち、実機で確かめたことと、このリポジトリのコードで裏付けが取れることだけをまとめています。Brain 向けにほかのエミュレータを移植するとき、作業を始める前に AI に読ませることを想定しています。

実機で確かめた機種は SHARP Brain PW-G5300 だけです。ほかの機種での動作は確かめていません。

各項目の最後の( )は、もとにした開発メモの記録です。開発メモでは、作業の区切りを「ラウンド」と呼んでいます。開発メモはリポジトリに入れていません。

v1.0.0 より前の直しは、コミット a8cdb9b7(コアの直し)と 660ef186(フロントエンド)にまとめて入っています。

## 全体の作り

- PopSG は libretro のフロントエンドとして作っています。`platform/libretro/libretro.c` をそのままコンパイルし、`CE/ce_main.c` が `retro_init()`・`retro_load_game()`・`retro_run()` を呼び、画面・音・入力・環境のコールバック(`retro_set_*` に渡すもの)を実装しています(開発メモの「アーキテクチャ・実装済みのファイル」)
- コアで変えたファイルは [`LICENSING.md`](LICENSING.md) の2節にまとめています
- コアの `retro_get_system_info()` は `need_fullpath = true` を返します。PopSG は ROM をメモリに読まず、`retro_game_info` の `path` だけを渡し、コア(`PicoLoadMedia()`)がファイルを開きます(`ce_main.c` の `PickRom()` のコメント)(開発メモの「アーキテクチャ・実装済みのファイル」)
- 68000 は Cyclone、Z80 は DrZ80 を使っています。どちらも ARM のアセンブリで書かれたもので、実行時に機械語を作る仕組み(`cpu/drc/cmn.c`)は使いません。32X(`-DNO_32X`)と SVP の再コンパイラ(`pico/carthw/svp/compiler.c`)はビルドから外しています(`CE/Makefile` の冒頭のコメント)(開発メモのラウンド5〜ラウンド8、2026-08-08、ラウンド19、2026-08-10)
- `AppMain.exe` が使う DLL は `COREDLL.dll` だけです。`arm-mingw32ce-objdump -p AppMain.exe` で確かめられます(開発メモの「v1.0.6 の2回目」、2026-10-08)

## ビルド

- `CE/Makefile` は `-march=armv5te -mno-unaligned-access` を付けています。`-mno-unaligned-access` が効くのは C のコードだけで、手書きのアセンブリ(`draw_arm.S` など)には効きません(下の「コアで直したこと」)(開発メモのラウンド12、2026-08-08)
- `cpu/drc/cmn.c` は、4096 バイトにそろえた配列が、このツールチェーンのオブジェクト形式(そろえられるのは 8 まで)ではコンパイルできませんでした。32X と SVP の再コンパイラを外した構成では呼ばれないので、ビルドから外しています(開発メモのラウンド2、2026-08-08)
- `pico/cd/cdd.c` は `off_t` を使いますが、cegcc の `stdio.h` からは `off_t` が入ってきません。`CE/Makefile` でこのファイルだけ `-include sys/types.h` を付けています(開発メモのラウンド2、2026-08-08)
- cegcc には `strerror()`・`perror()` の実装がありませんでした。`CE/ce_strerror_stub.c` で用意しています。`mmap()` などは `CE/ce_mmap_stub.c`(`VirtualAlloc` などを使う)、Sega Pico のペンの絵を読む PNG の関数は `CE/ce_rpng_stub.c`(読めなかったと答える)で用意しています(開発メモのラウンド2、2026-08-08)
- `platform/common/version.h` は `REVISION` が定義されている前提です。`CE/Makefile` で `-DREVISION=\"-CE\"` を渡しています(開発メモのラウンド2、2026-08-08)
- Cyclone の `Cyclone.s` は、ホストの C++ のツールで作ります。設定の既定(`HAVE_ARMv6`=1)のままだと ARMv6 の命令(`sxtb`・`sxth`・`uxth`)が入るので、`HAVE_ARMv6=0` で作り、`CE/cyclone/Cyclone.s` に置いています。作り方は [`cyclone/README.txt`](cyclone/README.txt) にあります(開発メモのラウンド6とラウンド7、どちらも 2026-08-08)
- Cyclone の `tools/idle.s` は、別のセクションのシンボルの差(`.word idle_data - offset_table`)を使っていて、cegcc(PE/COFF)ではアセンブルできませんでした(`cannot represent BFD_RELOC_32_PCREL relocation`)。`ldr rX, =symbol` で番地を読む形に書き換えたものを `CE/cyclone/idle.s` に置いています(開発メモのラウンド7とラウンド8、どちらも 2026-08-08)
- `draw_arm.S`・`draw2_arm.S` が読む `pico/pico_int_offs.h` は、上流の `tools/mkoffsets.sh` では作れませんでした。`/opt/cegcc/bin/arm-mingw32ce-gcc` の「cegcc」の中の「gcc」で名前を切ってしまうことと、cegcc の出力ではセクションの名前が `.rdata` であることが理由です。`tools/mkoffsets_ce.sh` で作っています(開発メモのラウンド10、2026-08-08)
- `-D_ASM_DRAW_C` は `pico/draw.c` と `pico/draw2.c` の両方を切り替えます。`draw_arm.S` だけを入れるとリンクで止まったので、`draw2_arm.S` も一緒に入れています(開発メモのラウンド10とラウンド11、どちらも 2026-08-08)
- `.S` のファイルに `-include stddef.h` を付けると、C の `typedef` がアセンブラに渡ってエラーになります。`.S` には `CFLAGS` ではなく `ASCPPFLAGS` を使っています(`CE/Makefile`)(開発メモのラウンド10、2026-08-08)
- cegcc の `libcoredll.a` には `SetStretchBltMode`・`TransparentBlt`・`Arc`・`Pie`・`Chord` がありません(`RoundRect`・`StretchBlt` はあります)。`arm-mingw32ce-nm` で確かめられます。メニューのアイコンの円弧は `ce_bmpfont.c` の `DrawArcPoly()` で点をつないで描き、マスコットの絵は背景の色を合成した BMP にしています(開発メモのラウンド56、2026-09-04、ラウンド61とラウンド62、どちらも 2026-09-21)

## 画面

- GAPI(`gx.dll`)は使っていません。描画は GDI だけでしています(開発メモのラウンド34、2026-08-28)
- 画面の大きさは 480×320 でした(実機のログ)。今のコードは `ce_display.c` の `CeDisplayInit()` で `GetSystemMetrics(SM_CXSCREEN / SM_CYSCREEN)` から取っています(開発メモのラウンド34、2026-08-28)
- 画面と同じ大きさの RGB565 の DIB セクション(`CreateDIBSection`、`BI_BITFIELDS`、`biHeight` を負にして上から下の順)にアプリのコードで拡大して書き、`BitBlt` で等倍のまま画面へ送ります(`ce_display.c` の `CeDisplayBlitRGB565()`)(開発メモのラウンド34、2026-08-28)
- メガドライブの横 320 画素(H40)のゲームで、表示の大きさごとに実機のログ(`perf: blit`)で転送の時間を測りました。どれも、前に使っていた GAPI の版より短くなりました(開発メモのラウンド34とラウンド35、どちらも 2026-08-28)

| 表示 | GDI(平均 / 最大) | 前の GAPI の版(平均 / 最大) |
|---|---|---|
| x1 | 3ms / 4ms | 6〜7ms / 7〜9ms |
| x1.5 | 5ms / 6〜7ms | 8〜9ms / 9〜11ms |
| Wide | 6ms / 7〜8ms | 9ms / 10〜11ms |
| Full | 7ms / 8〜9ms | 9ms / 10〜11ms |

- コアはゲームギアの画面を 160×144 に切り取って渡します(`libretro.c` が `POPT_EN_GG_LCD` を立てる、`pico/mode4.c`)。幅 160 で来るのはゲームギアだけなので、`ce_display.c` の `ComputeGeometry()` は `srcW == 160` のときだけゲームギア用の大きさ(x1.5 は 320×288、Wide は 400×320、Full は 480×320)にしています(開発メモのラウンド37、2026-08-28)
- ゲームギアの Wide(160 → 400、5/2 倍)は、1画素ずつ位置を計算していたときは書き込みが 9ms でした。4画素 → 10画素を32ビットの書き込み5回にする形(`s_scale5over2`)にしたら 2ms になり、`retro_run` の平均は 17〜20ms から 13〜15ms になりました(実機のログ)。表示も実機で確かめました(開発メモのラウンド37、2026-08-28)
- 表示の大きさや元の画像の大きさが変わったときは、画面全体を一度 `PatBlt` で黒く塗ってから描きます。メガドライブの H32 と H40 が切り替わるゲームで、前の画像の縁が残らないことを実機で確かめました(開発メモのラウンド34、2026-08-28)
- GDI でウィンドウに直接描くので、ダイアログを閉じて見えた部分は描き直す必要があります。`ce_main.c` の `WndProc` の `WM_PAINT` で、ゲームを読んでいれば `CeDisplayForceRepaint()` を呼びます。メニューを開いて閉じても後ろのゲームの画面が残ることを実機で確かめました(開発メモのラウンド34、2026-08-28)
- メニューや設定画面の文字は、`AppMain.exe` に入れたビットマップフォントを `SetPixel` で描いています(`ce_bmpfont.c`)。フォントのファイルは要りません(開発メモのラウンド31、2026-08-26)。日本語の表示を実機で確かめました(開発メモのラウンド32、2026-08-26)
- TrueType のフォントファイルを `AddFontResourceW` で読み込んでいたころ、アプリの起動と終了を繰り返すと日本語の文字が□になり、電源を切ると直りました(実機)。今はフォントファイルを読み込みません(開発メモのラウンド16、2026-08-08、ラウンド31、2026-08-26)

## 速さ

- `perf: core` の行(68000・Z80・描画・音の区間の時間。1ms 単位の `GetTickCount()` で測るもので、今のコードには入っていません)で、メガドライブのゲームの対戦中の時間を測りました(実機のログ)(開発メモのラウンド5・ラウンド9・ラウンド13、どれも 2026-08-08)
  - 68000 を C の Fame から Cyclone にして、`idle.s` も入れたあとで、68000 の区間は 10〜11ms から 8.8ms になりました
  - 描画を `draw_arm.S`・`draw2_arm.S` にしたあとで、描画の区間は 5〜6ms から 2〜3ms になりました。このとき、68000 の区間は対戦の終わりのほうで 7.0ms、`retro_run` の平均は 26〜29ms でした
- GAPI から GDI に替えたあと、体感では、ゲームギアとマスターシステムのゲームが速く動きすぎました。ログにも `ring overrun` が出ていました。このとき、メインのループには、フレームの速さを合わせる処理がありませんでした(開発メモのラウンド38、2026-08-28)
  - 今のコードは、waveOut が開けているときは、`retro_run` の前に、リングにたまった音が 64ms(`CE_FRAME_PACING_HIGH_MS`)以下になるまで `Sleep(1)` で待ちます(最大120回)。開けていないときだけ `GetTickCount()` で合わせます(`ce_main.c` の `WinMain`)(開発メモのラウンド38、2026-08-28)
  - 体感では、実機で速さが戻りました。ゲームギアのゲームのログでは `ring overrun` は出ず、`audio underrun` は起動した直後の1回だけでした(開発メモのラウンド38、2026-08-28)
- `CeLog()` が1行ごとにファイルを開いて閉じていたころ、メガCD のゲームでデバッグログを ON にすると、体感では OFF のときより音が途切れ、重くなりました。今は `CeLog()` はメモリのバッファに入れるだけで、別のスレッドが 200ms ごとにまとめて書きます(`ce_log.c`)(開発メモのラウンド53、2026-09-02)

### メガCD

- メガCD のゲームは、PW-G5300 では実時間に追いつかず、音が途切れます(実機)(開発メモのラウンド49、2026-08-29)
- メガCD のゲームを、起動から終了まで1回遊んだログ(フレームスキップ 1、Full、音 44000Hz・16 ビット、バッファ 8192)では、60フレームごとの `retro_run` の平均は、6〜79 番目の区切りの平均で 18.1ms でした。v1.0.2 をもとにしたテスト用の exe でも同じでした(開発メモの「v1.0.3 の作業」、2026-10-05)
- 別のメガCD のゲーム(以下、ゲーム A)のオープニングのアニメを、計測用の exe(公開していないもの。約1ms ごとに、いま動いている区間を数える。計測のため、8フレームに1回は描かない)で測りました(フレームスキップ 0、Full、音 44000Hz)(開発メモの「メガCD の速さの計測」、2026-10-05〜2026-10-07)
  - 1フレームの内訳は、画面の転送 6.1ms、サブの 68000 4.8〜5.0ms、描画 2.8〜2.9ms、CD のデータの読み込み 2.0〜2.1ms でした
  - サブの 68000 は1フレームに 207,950 サイクル動いていて、待ちのループを飛ばす処理は効いていませんでした
  - BIN のイメージでは、`cdd_read_data` が1回に 2048 バイトだけ読むので、次のセクタとずれて、読むたびにシークしていました(10秒で751回読んで751回シーク)。2352 バイトずつ読む形にするとシークは0回になりましたが、読み込みの時間は 2.0〜2.1ms から 1.8〜2.0ms になっただけでした。この直しは公開版に入れていません
  - 表示を x1 にすると、画面の転送は 2.8〜2.9ms になりました
- 同じ計測用の exe で、Full の拡大で同じ元の行を使う行を、前の行からコピーする形も試しました。パソコンでは出力が1バイトも違わないことを確かめましたが、実機では、描いたフレームが約 0.5〜0.7ms 遅くなりました。公開版には入れていません(開発メモの「メガCD の速さの計測」、2026-10-07)
- `GetIdleTime()` は PW-G5300 で使えました(`Sleep(100)` の前後で +100ms)。ゲーム A のオープニング(フレームスキップ 1、Full、音 44000Hz)では、CPU が空いていたのは1フレームあたり約 0.7ms でした(開発メモの「メガCD の速さの計測」、2026-10-07)

## 音

- waveOut は1チャンネル(`nChannels = 1`)で開き、コアの左右の音を平均して1つにしています(`ce_audio.c`)
- 音のリングバッファの大きさは、Sound Config で 4 / 8 / 16 / 32 / 64 / 128 KB から選べます(中はフレーム数で、2048〜65536)。どの大きさでも音が鳴り続けることを実機で確かめました(開発メモのラウンド41、2026-08-28)

## 入力

- キーは `GetAsyncKeyState` で毎フレーム読みます(`ce_input.c` の `CeInputPoll()`)
- 斜め(右上など)の行は、1つのキーで2方向を押します。`CeInputPoll()` で全部をいったん 0 にしてから OR でまとめます。斜めの入力が効くことを実機で確かめました(開発メモのラウンド30、2026-08-17)
- コアの `picodrive_input1`・`picodrive_input2` の問い合わせに、いつも `"6 button pad"` と答えています(`ce_video.c` の `CeVideoEnvGetVariable()`)。6ボタンのゲームで X・Y・Z・MODE が効くことを実機で確かめました(開発メモのラウンド28とラウンド29、どちらも 2026-08-15、「v1.0.3 の作業」、2026-10-05)
- マスターシステムとゲームギアのボタンは2つで、コアが読むのは B 行と C 行のボタンです。マスターシステムとゲームギアのときだけ、A 行のキーも C 行(ボタン2)に足しています(`CeInputPoll()` の最後、`PicoIn.AHW & (PAHW_SMS | PAHW_GG)`)。実機で確かめました(開発メモのラウンド29、2026-08-15)
- UI が日本語のときは、コアの `picodrive_region` の問い合わせに `"Japan NTSC"` と答え、英語のときは `"Auto"` と答えます(`CeVideoEnvGetVariable()`)。実機で確かめました(開発メモのラウンド4、2026-08-08)

## ダイアログ

- リストボックスで A〜Z のボタンを押すと、選択が動きました。`ce_fileopen.c` の `FileListCtrlProc` で、空白以上の `WM_CHAR` を元のリストボックスに渡さずに捨てています(開発メモの「v1.0.4 の1回目」、2026-10-07、コミット d3447c6b、タグ v1.0.4)
- `RoundRect()` の最後の2つの引数は、角の楕円の直径です。14 を渡したときは、実機では角がほとんど丸く見えませんでした。今はボタンの短いほうの辺の長さを渡しています(`ce_bmpfont.c` の `CeBmpFontDrawOwnerButtonTheme()`)(開発メモのラウンド62とラウンド63、どちらも 2026-09-21)
- `RoundRect()` はボタンの矩形の内側の角の丸い形しか塗らないので、四隅が白く残りました。先に矩形全体をダイアログの背景の色で `FillRect()` してから `RoundRect()` を呼ぶ形にしたら直りました(実機)(開発メモのラウンド64とラウンド65、どちらも 2026-09-21)
- アイコン(.ico)には AND マスクを入れます。Pillow で書いた .ico にはマスクが無く、実機のエクスプローラーで、アイコンの透明な部分が黒くなり、左下に白い縞が出ました。マスクを足したら直りました(開発メモの「引継ぎ(2026-10-02 区切り・前半)」と「アイコン修正の実機確認」、2026-10-02、コミット 5e021cf2、タグ v1.0.1)

## ファイルと設定

- 設定は `AppMain.exe` と同じフォルダの `popsg.cfg` に書きます(`ce_config.c`)
- CRT の `fopen()` は、中で文字列を CP_ACP で変換します。PopSG はパスを UTF-8 で持っているので、`CE/compat/stdio.h` で `fopen` を `ce_fopen_utf8()`(`ce_fopen_utf8.c`)に置き換え、`MultiByteToWideChar(CP_UTF8, …)` で戻してから `_wfopen()` で開いています。`-Icompat` はコアのファイルにも効くので、コアの `fopen()` もここを通ります(開発メモのラウンド58、2026-09-05)。日本語を含むフォルダの ROM を読み込めることを、実機で確かめました(開発メモの「日本語のフォルダの実機確認」、2026-10-09)
- カートリッジのセーブ(`.srm`)は、メニューを開いたとき、別の ROM を開くとき、ゲーム中の30秒ごと、終了のときに書きます(`ce_main.c`)(開発メモの「v1.0.6 の1回目」、2026-10-07、「v1.0.6 の2回目」、2026-10-08、コミット 3e98cb28、タグ v1.0.6)
  - 30秒ごとと終了のときは、中身が読み込んだとき、または前に書いたときと同じなら書きません(`CeSaveSramIfChanged()`)。`.srm` がまだ無いゲームでは、中身が変わるまで、どの時点でも書きません(`CeSaveSramCheckpoint()`)。メガCD の本体のバックアップ RAM は、コアが起動のときに 0 とフォーマットの印で埋め(`pico/cd/mcd.c` の `PicoPowerMCD()`)、大きさはいつも 0x2000 です
  - セーブしないで遊んだメガCD のゲームでは `.srm` ができないこと、ゲームの中でセーブしたメガCD・メガドライブ・ゲームギアのゲームでは、起動し直して続きから遊べることを実機で確かめました
  - コアは、1フレーム以上動いたあとで、カートリッジ・マスターシステムのセーブ領域がすべて 0 なら、大きさ 0 を返します(`libretro.c` の `retro_get_memory_size()`)。大きさが 0 のときは書きません
- ステートセーブは、`retro_serialize_size()` の大きさのバッファに `retro_serialize()` で書かせて、まるごとファイルに書きます。コアは後ろの使わない部分を書かないので、`CeSaveState()` では `calloc()` で 0 にしています。メガドライブ・マスターシステム・ゲームギアで、保存と読み込みを続けて繰り返して問題が無いことを実機で確かめました(開発メモの「v1.0.3 の作業」、2026-10-05、コミット 3707d248、タグ v1.0.3)

## メガCD の BIOS

- コアは BIOS を `RETRO_ENVIRONMENT_GET_SYSTEM_DIRECTORY` で聞いたフォルダから開きます(`libretro.c` の `find_bios()`)。これに答えていなかったころは、メガCD の .cue を選ぶと「Failed to load ROM.」になりました。答えるようにしたら、起動画面まで進みました(実機)(開発メモのラウンド49、2026-08-29)
- 今のコードは、BIOS をファイルの名前ではなく中身(0x100 の「SEGA」、0x1F0 の地域の文字)で見分けます(`ce_main.c` の `ProbeMegaCdBiosFileW()`)。コアが正式な名前で BIOS を開こうとしたとき、`ce_fopen_utf8()` から呼ぶ `CeMegaCdBiosRedirect()` が、見つけたファイルに差し替えます。ファイルのコピーや名前の変更はしません。名前が正式でない BIOS が自動で見つかることを、日本の BIOS で実機で確かめました。北米・欧州の BIOS は、動作を確かめていません(開発メモのラウンド59、2026-09-05)

## 終わり方

- 終了は `ce_main.c` の `CeShutdown()` から `ExitProcess()` を直接呼びます。セーブの書き込みとログの書き出し(`CeLogShutdown()`)は `ExitProcess()` の前にしています(開発メモのラウンド53、2026-09-02)

## コアで直したこと

- `pico/pico_int.h`: `NO_32X` でビルドすると、32X を外したときの代わりの定義に無い関数・変数があり、コンパイルとリンクが止まりました。足りない分を足しています。変数の実体は `CE/ce_32x_stub.c` にあります(開発メモのラウンド2、2026-08-08)
- `pico/draw_arm.S`: ROM を選んだあと、ゲームの画面が出る前に画面が暗くなり、電源が落ちました。BER の記録は Datatype Misalignment の例外でした。例外の番地を、strip する前の .o からリンクし直した exe で `arm-mingw32ce-nm -n` で引くと、`FinalizeLine555` の `ldr r2, [r8, #OFS_Pico_m_hardware]` でした。この項目は1バイトで、位置は 0x47 です。`ldrb` にしたら落ちなくなり、絵も正しく出ることを実機で確かめました。`draw_arm.S`・`draw2_arm.S` の、`OFS_*` を使う32ビットの読み書きをすべて調べ、4の倍数でない位置はこの1か所だけでした(開発メモのラウンド12とラウンド13、どちらも 2026-08-08)
- ゲームを遊んだあとで別の ROM を開くと、lunoka 氏のゲーム『Mai Nurse』のタイトル画面が飛ばされました。アプリを起動して最初に開いたときは飛ばされませんでした(開発メモの「ゲームの途中で別の ROM を開くとタイトル画面が飛ばされる件」、2026-10-05、コミット e4d8d4df、タグ v1.0.2)
  - `pico/memory.c` の `padTHLatency`・`padTLLatency`・`padTHTimeout` は、パッドを読むタイミングを 68000 のサイクル数で覚えています。`PicoPower()` はサイクル数を 0 にしますが、この3つは元に戻しません
  - 実機のログでは、ROM を読み込んだ直後に端子1を読んだ値が、起動して最初に開いたときは `ff`、別のゲーム(以下、ゲーム B)を遊んでから開いたときは `a3` でした
  - PopSG は `retro_init()` を1回だけ呼び、ROM を替えるたびに `retro_load_game()` を呼びます。`retro_set_controller_port_device()` は呼びません。そこで、`ce_main.c` の `LoadRomFlow()` で `retro_load_game()` が成功した直後に、コアの `io_ports_reset()` を呼んでいます。コアのファイルは変えていません。ゲーム B を遊んでから『Mai Nurse』を開いてもタイトル画面が出ることを実機で確かめました

## デバッグの進め方

- アプリが例外で落ちたときは、[Brain Exception Reporter(BER)](https://github.com/Sgch/ber) で例外とレジスタを記録しました(開発メモのラウンド12、2026-08-08)
- デバッグログ(Video Config の「デバッグログを有効にする」)は既定で OFF です。`WinMain` で設定を読んでから有効にするので、それより前の行はログに出ません(`ce_main.c`)(開発メモのラウンド39、2026-08-28)
- ログを ON にすると、60フレームごとに `perf: retro_run avg=… max=… blit avg=… max=…` の行が出ます(開発メモのラウンド45、2026-08-29)

## 動作を確かめていないもの

- 32X はビルドから外しています。Sega Pico、SVP、VGM・VGZ の再生は、動作を確かめていません(開発メモの「次の版の作業」、「v1.0.3 の作業」、2026-10-05)
- マスターシステムの FM 音源は使っていません。コアの `picodrive_smsfm` の問い合わせに答えず、`PicoIn.opt` に `POPT_EN_YM2413` が入らないためです(開発メモの「v1.0.3 の作業」、2026-10-05)
